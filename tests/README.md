# Verification

Run `build.ps1 -RunTests` from the repository root against a local game installation and the pinned build dependencies.

The 1.3.5 regressions cover a pursuit route beyond the previous awareness radius whose first leg goes away from the target, incremental search, waypoint advancement, closed gates and retry after reopening. The combat route test keeps a shot on one opponent while terrain blocks a second sightline. Engagement cases cover fighting while outnumbered, committing briefly to cover under lethal pressure, returning to pursuit and prioritizing KOTH. The metadata audit checks the reward shortcut's input path and how the replicated bot roster connects to native first-spawn nameplates. In-game multiplayer testing is still needed for the replication timing.

RiskOfPVP 1.3.4 was compiled against Risk of Rain 2 1.5.0#1224 on 21 November 2026. The suite passes 1,037 rule assertions, 560 production item-pool/controller assertions, 13 production graph/locomotion assertions, 16 production combat-catalog assertions and 78 real BepInEx configuration/transport assertions: 1,704 total. The metadata audit passes 66 scoped native hook targets and the retained host-authority, survivor, equipment, reward and explicit-assembly-loading guards. Compilation passes without warnings/errors. The optional metadata audit also passes 14 Aerolt-menu/DropIn contracts against the existing reference DLLs.

Controller cases distinguish button requests from real activation events and state completion. The ten-second aim-to-fire case starts with sideways aim, alternates native A/D aim, leaves other skills unavailable and requires the production aim helper/controller to keep turning and firing at an unmoving target. It also covers a stale utility request. Native input-to-aim ordering and production wiring are separately checked against game metadata. Additional cases cover continuous automatic primary input, independent versus shared state machines, native cooldown cycles, must-key-press edges, learned primary/secondary charge release, scope priority, self-healing, physical range versus preferred AI spacing and forbidden loadouts.

The combat-catalog suite executes the production learning registry and observers with native API adapters: incremental configuration indexing, actual emission attribution, authoritative hit/proc evidence, threat estimates with armor and host damage rules, observed recovery versus multistock skills, immediate skill replacement, death/respawn, event cleanup and post-match suspension. Pure policy cases exercise proc-aware valuation, falloff, novice/expert adaptation and brief inactivity. They do not simulate arbitrary custom skill scripts.

Route cases execute production discovery and local obstacle recovery with a graph/physics adapter, including wall-tangent escape without repeated reversals, unsafe floor rejection, the standing start node, commitment, immediate retreat, arrival, query bounds, airborne fallback and KOTH containment. Rules cases cover displacement stalls despite changing goals, route revisits, advancing dodges, damage/defeat memory across respawns and diminishing defensive investment. Observed burst, proc and damage-over-time evidence changes defensive item scoring; production reward tests retain host bans.

A 40-reward scripted high-pressure build picked 23 defensive/sustain rewards and 17 offensive rewards. This checks against always choosing one role; it is not a claimed ideal build or player win rate. The production chooser also evaluates 1,000 600-pickup offers in the catalog adapter. That timing excludes Unity physics, native pathfinding, inventory callbacks, animation, rendering and networking.

No game was launched or installed profile changed during this verification. Live map navigation, survivor animation, damage balance, multiplayer observation and sustained CPU cost remain gameplay checks. Historical charts in the main README describe the earlier recorded comparison through commit `bece477`; they have not been relabelled as measurements of 1.3.4.
